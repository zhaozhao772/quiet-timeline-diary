5. 更新代码到 GitHub Pages 的方法
═══════════════════════════════════════

沙箱直连 github 会被 DNS 污染（解析成 198.18.x.x 假 IP），必须 --resolve 固定 IP。三个固定 IP：

api.github.com:443:140.82.112.6                  # API 操作（备用 140.82.113/114/115.6 轮换）
raw.githubusercontent.com:443:185.199.108.133    # 验证 raw 内容
zhaozhao772.github.io:443:185.199.108.153        # 验证 Pages 线上效果

【部署脚本（推荐，一条命令搞定）】
python3.11 /root/.codebuddy/deploy_gh_pages.py          # 部署 /workspace/index.html
python3.11 /root/.codebuddy/deploy_gh_pages.py --check  # 只读验证（不推送）
脚本内建：15 次重试 + 4 个 API IP 轮换 + 409 自动重取 sha 再 PUT
        + 仓库回读比对 MD5 + Pages 轮询（带 ?t= 时间戳防 CDN 缓存）
token 自动从 /root/.codebuddy/gh_token 读取，无需手动传

【手动 curl 流程（脚本丢失时重建用）】
# 1. GET 拿当前文件 sha
curl --resolve "api.github.com:443:140.82.112.6" --http1.1 \
  -H "Authorization: token $(cat /root/.codebuddy/gh_token)" \
  -H "Accept: application/vnd.github+json" \
  "https://api.github.com/repos/zhaozhao772/quiet-timeline-diary/contents/index.html" \
  -o /tmp/get.json
# 2. base64 编码本地文件
base64 -w0 /workspace/index.html > /tmp/content.b64
# 3. 组 JSON（sha + message + content）写临时文件，PUT 提交
#    务必 --data-binary @/tmp/put.json + -o /tmp/put_resp.json 文件中转，不要内联命令行

【409 冲突处理】
报 409 或 "sha" wasn't supplied → sha 过期/没拿到，重新 GET sha 再 PUT（最多 3 轮）

【网络抖动】
重试循环 15 次 + IP 轮换 + 间隔递增；401 是 token 失效，立即停止报告用户，不重试
curl 偶发 http_code=000 / 响应截断 → 一律用 -o 文件 下载，不要捕获 stdout

【部署后确认（双验证）】
1. API 回读仓库文件内容，与本地比对 MD5
2. curl Pages 地址加 ?t=$(date +%s)，轮询直到内容一致（CDN 滞后 1-2 分钟，构建偶报 errored 会自动重试）

【Playwright 测线上页面】
Chromium 对 github.io 域名解析异常，启动参数加：
--host-resolver-rules=MAP zhaozhao772.github.io 185.199.108.153

6. 缓存策略
═══════════════════════════════════════

本项目无 Service Worker，不需要升 CACHE_NAME / ?v= 参数（与"昭昭个人站"不同！）。

改动后看不到效果的排查顺序：
1. Pages CDN 滞后 1-2 分钟 → 验证 URL 加 ?t=$RANDOM 时间戳
2. 手机浏览器缓存 → 用户侧强刷新 / 无痕窗口打开
3. 沙箱文件没改对 → md5sum 对比线上与本地

【交付方式铁律】用户手机上打开沙箱文件卡片会失败（已多次反馈）。
给用户代码/文档一律走两条路：聊天内直接输出全文 + GitHub raw 网址，不走文件卡片。

【导入导出】

【UI 工具】
showModal(opt)/closeModal()/toast(msg)/downloadFile(name,content,type)

日期格式化：fmtDate / fmtMD / fmtTime / fmtCNDate / fmtCNDateTime / fmtWeek

⚠️ 五条易踩的坑：
1. 增删改记录必须 IDB + writeMirror 双写，漏一边刷新后状态不一致
2. 改返回逻辑先看 state.detailFrom / state.returnTo 两条回跳链路
3. 圆点选择器必须作用域限定，全局 .dot 会污染另一个视图的圆点
4. 用 Edit 工具改含真实图标 base64 的 index.html 会因 Read 截断失败
   → 先 Grep 定位行号，按行号片段读取后再 Edit；或改文档版后 icon_slot.py merge
5. rename-input id 被 renameFolder/createFolder/renameRecord 共用，
   靠 modal 时序隔离，改动弹窗逻辑时注意
